## 2026-11-13 MPS GPU 执行环境修正

定位结果：同一安装在普通受限命令环境中 `mps_built=true`、`mps_available=false`；通过宿主正常授权的本机执行环境中 `mps_available=true`，实际 GPU 矩阵运算通过，`mps_compute_verified=true`。此前 CPU 任务不能据此判定为模型不兼容，执行环境访问权限会影响设备选择。

本次更新增加 GPU 运算预检、明确的访问失败原因和启动设备提示；worker 核对模型实际驻留设备，并在结果记录 device 与 precision。默认 auto 继续优先 MPS、允许有说明的 CPU 回退；显式 `--device mps` 不将整任务回退 CPU。保持 float32、原模型窗口、重叠与内存控制。

9 项回归测试通过，含新增的 GPU 运算失败诊断和强制 MPS 失败不重试 CPU。真实 CLI 在受限环境中使用 `--device mps`，实际以退出码 1 明确报错，未等待既有推理锁、未生成输出、未回退 CPU；本机授权环境的实际 MPS 预检通过。

用户要求保留正在进行的 CPU 分离任务，本次未停止/重跑该任务，也未同时加载第二个分离模型；因此本次没有新的全曲 GPU 分离或速度基准。此前两指定模型的真实 GPU 分离记录保留在初版历史记录中。更新后的格式与仅可播放性确认逻辑继续通过回归测试。

## 2026-11-13 格式与可播放性迭代

当前行为：对话中询问未指定的输出格式，默认选项为与源文件格式和可读取参数一致；CLI 默认 `--format source`。只对最终编码完成的两个文件各做一次完整解码，确认可播放。取消逐段音频核验、静音/能量/NaN 检查以及与原曲的时长和内容比较。保留模型推理本身的分块内存控制和模型文件 SHA-256 校验。

本次 7 项自动回归测试全部通过：

- 真实 FFmpeg 编码、探测和解码覆盖 WAV、FLAC、MP3、M4A/AAC、AIFF，默认导出保留源格式、采样率、声道、PCM 位深或 MP3 码率；另测 M4A/ALAC 和 FLOAT WAV。
- 可播放的静音音频和不同时长/声道素材通过；损坏文件被拒绝。没有进行音质或内容评分。
- 模拟模型推理的端到端流程实际执行 MP3 编码与解码，确认只检查两个最终 MP3 文件后发布；未对中间 WAV 或推理片段进行核验。
- 模拟 MPS OOM→CPU 重试、目标路由、文件防覆盖、模型缓存回归通过。

Skill 元数据校验、README 中 shell 示例语法、ZIP 完整性与大文件排除检查通过。本次未重新执行真实模型推理：既有另一个音频处理任务占用推理锁，已停止本次等待锁的短测试，未中断既有任务。模型加载和设备路径沿用下述初版实测结果；本次新格式和最终解码使用真实 FFmpeg 测试。未测试宿主自动触发格式询问或 ChatGPT 实际导入。
